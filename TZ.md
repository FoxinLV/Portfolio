# Техническое задание

## 1. Общая информация

**Наименование проекта:** персональное портфолио проектов  
**Тип системы:** статическое веб-приложение  
**Размещение:** GitHub Pages  
**URL:** `https://username.github.io/portfolio/`  
**Frontend:** React + Vite  
**Хранилище данных:** Yandex Object Storage S3  
**Backend:** отсутствует

На первом этапе сайт должен содержать два основных раздела:

- Проекты;
- Обо мне.

Разделы «Кейсы», «Технологии», «Статистика» на первом этапе не реализуются и в интерфейсе не отображаются.

---

# 2. Назначение сайта

Сайт предназначен для публичного представления профессионального портфолио разработчика.

Основная задача сайта — показать реализованные проекты в хронологическом порядке, используемые технологии, направления деятельности и информацию об авторе.

Портфолио должно быть рассчитано на разработчика широкого профиля и позволять демонстрировать проекты различных типов:

- веб-разработка;
- backend-разработка;
- мобильные приложения;
- аналитика и BI;
- инфраструктура;
- автоматизация;
- интеграции;
- внутренние корпоративные системы;
- инженерные и собственные проекты.

Контент проектов не должен храниться непосредственно в исходном коде сайта.

Источником информации является Yandex Object Storage.

# 3. Общая архитектура

Архитектура системы:

```text
                    GitHub
                       │
                       │ push в main
                       ▼

                       │
                 npm run build
                       │
                       ▼
                 GitHub Pages
                       │
                       │ HTTPS
                       ▼
              React + Vite SPA
                       │
                       │ GET
                       ▼
            Yandex Object Storage
                       │
             ┌─────────┴─────────┐
             │                   │
        profile.json          projects/

                   ┌─────────────┼─────────────┐
```

GitHub Pages отвечает исключительно за:

- загрузку frontend;
- отображение интерфейса;
- маршрутизацию;
- получение данных;
- фильтрацию;
- сортировку;
- поиск;
- отображение проектов.

Yandex Object Storage отвечает за:

- описание проектов;
- изображения;
- приложения;
- документы;
- файлы проектов;
- данные раздела «Обо мне».

Собственный backend отсутствует.

# 6. Yandex Object Storage

Для портфолио рекомендуется использовать отдельный bucket.

Например:

```text
portfolio-projects
```

Поскольку приложение должно получать данные непосредственно из браузера, для bucket предусматривается публичный доступ:

- чтение объектов — для всех;
- чтение списка объектов — для всех.

Следует учитывать, что публичный List Objects позволяет анонимному пользователю увидеть имена объектов в bucket. Поэтому в этом bucket не должны храниться приватные документы, секретные данные, API-ключи, конфигурации, исходные данные внутренних систем и другая непубличная информация.

# 7. CORS

Yandex Object Storage должен разрешать браузерные запросы с GitHub Pages.

Необходимо настроить CORS минимум для:

```text
GET
HEAD
```

Разрешённый Origin:

```text
https://username.github.io
```

Для локальной разработки дополнительно допускается:

```text
http://localhost:5173
```

В production рекомендуется не использовать:

```text
*
```

если в этом нет необходимости.

# 9. Правила идентификаторов

Каждый проект должен иметь постоянный уникальный ID.

Пример:

```text
bvs-analytics
```

```text
bvs-field-app
```

```text
helped-jesus
```

Рекомендуемый формат:

```text
[a-z0-9-]
```

Допускаются:

- латинские буквы в нижнем регистре;
- цифры;
- дефис.

Не использовать:

- пробелы;
- кириллицу;
- специальные символы;
- даты в качестве основного ID.

ID после публикации проекта желательно не изменять.

# 10. Получение списка проектов

При загрузке раздела «Проекты» frontend должен выполнить запрос списка объектов Yandex Object Storage.

Запрашивать только prefix:

```text
portfolio/projects/
```

Frontend должен определить объекты:

```text
*/project.json
```

Например:

```text
portfolio/projects/bvs-analytics/project.json
portfolio/projects/bvs-field-app/project.json
portfolio/projects/helped-jesus/project.json
```

После получения списка frontend загружает соответствующие `project.json`.

Алгоритм:

```text
1. Получить List Objects.
2. Найти все объекты project.json.
3. Загрузить JSON каждого проекта.
4. Проверить обязательные поля.
5. Исключить status != published.
6. Отсортировать по date DESC.
7. Сформировать категории.
8. Сформировать список технологий.
9. Сформировать список направлений.
10. Рассчитать статистику.
11. Отобразить хронологию.
```

# 11. Кэширование

Полученные данные проектов должны сохраняться в памяти приложения на время текущей пользовательской сессии.

При переходах:

```text

```

не требуется повторно загружать все `project.json`, если данные уже находятся в памяти.

После полного обновления страницы:


должно выполняться новое получение данных из S3.

Благодаря этому новый проект, опубликованный через локальную административную систему, появляется в портфолио без нового deploy GitHub Pages.

# 14. Статус проекта

Поддерживать минимум:

```text
draft
published
archived
```

### draft

Проект находится в S3, но не отображается на публичном сайте.

### published

Проект отображается пользователям.

### archived

Проект сохранён в хранилище, но по умолчанию на сайте не отображается.

Frontend должен показывать только:

```text
status = published
```

# 16. Направления

Каждый проект относится к направлению деятельности.

На первом этапе предусмотреть:

```text
Aviation
Studio
WorkShop
```

Пример:

```json
"direction": {
  "id": "aviation",
  "name": "Aviation"
}
```

Назначение:

### Aviation

Проекты, связанные с авиацией, БВС, беспилотными системами, аналитикой налёта, техническим учётом и смежными системами.

### Studio

Коммерческие, пользовательские, веб- и программные проекты.

### WorkShop

Собственные разработки, эксперименты, инженерные проекты, прототипы, автоматизация и pet-проекты.

Архитектура не должна ограничивать список тремя направлениями.

Новые направления должны автоматически появляться в фильтре после публикации соответствующего проекта.

# 71. Конфигурация S3

Адрес bucket не должен использоваться напрямую в десятках компонентов.

Создать единый config.

Например:

```ts
export const STORAGE_CONFIG = {
  baseUrl: 'https://storage.yandexcloud.net/BUCKET_NAME',
  portfolioPrefix: 'portfolio',
  projectsPrefix: 'portfolio/projects',
  profilePath: 'portfolio/profile.json'
};
```

В дальнейшем endpoint должен легко изменяться.

---

# 72. Работа с относительными путями

В `project.json` используются относительные пути.

Например:

```json
"cover": "cover.webp"
```

Frontend должен автоматически получить:

```text
https://storage.yandexcloud.net/BUCKET_NAME/
portfolio/projects/bvs-analytics/cover.webp
```

То же самое для:

```text
gallery
files
```

Таким образом локальная система создания проектов не должна записывать полный URL bucket.

---

# 73. Безопасность

Frontend не должен содержать:

```text
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
Yandex IAM token
service account key
OAuth token
```

Для чтения публичного портфолио никакие ключи не используются.

Все запросы выполняются как анонимные.

---

# 74. Ограничение публичного контента

Поскольку чтение объектов открыто всем, любой человек, знающий URL объекта, сможет скачать файл.

Поэтому административная система перед публикацией должна считать любой файл внутри публичного bucket публичным.

В bucket запрещено помещать:

- пароли;
- API keys;
- персональные данные;
- конфиденциальные документы;
- закрытые корпоративные данные;
- внутренние конфигурации;
- дампы баз данных;
- `.env`;
- приватные исходные данные.

# 89. Критерии готовности

Система считается реализованной, если выполняются следующие условия.

1. Сайт доступен:

```text
username.github.io/portfolio/
```

2. GitHub Pages автоматически обновляется после push в `main`.

3. Главная страница открывает раздел проектов.

4. Проекты загружаются из Yandex Object Storage.

5. Для добавления нового проекта не требуется менять исходный код frontend.

6. `draft` проекты не отображаются.

7. `published` проекты отображаются.

8. Проекты сортируются по дате от новых к старым.

9. Проекты автоматически группируются по годам.

10. Работает поиск.

11. Работает фильтр по году.

12. Работает фильтр по типу системы.

13. Работает фильтр по технологии.

14. Работает фильтр по направлению.

15. Фильтры можно применять одновременно.

16. Работает отдельная страница проекта.

17. Отображается галерея проекта.

18. Прикреплённые файлы можно скачать.

19. Статистика рассчитывается автоматически.

20. Информация раздела «Обо мне» загружается из `profile.json`.

21. Сайт адаптирован под телефон.

22. Сайт корректно работает при отсутствии галереи или файлов.

23. Ошибка одного проекта не выводит из строя весь сайт.

24. В frontend отсутствуют секретные ключи Yandex Cloud.

25. Изменение проекта в Object Storage не требует повторной сборки GitHub Pages.

# 91. Основной принцип системы

Публичный сайт должен оставаться максимально простым:

```text
GitHub Pages
        ↓
React
        ↓
Yandex Object Storage
```

GitHub Pages содержит приложение.

Yandex Object Storage содержит контент.

Локальная административная система занимается созданием и публикацией контента.

Эти три компонента должны быть максимально независимы друг от друга.
